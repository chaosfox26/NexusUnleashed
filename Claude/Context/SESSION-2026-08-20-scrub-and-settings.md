## 4. NEXT FEATURE — cogwheel Settings panel (scoped, de-risked)

**the operator wants a Settings menu behind a cogwheel in nusl** (keep the launcher uncluttered) to edit realm
identity, writing `realm.json` (server reads it at boot; applies on next Start):
- **Server Name** (`RealmName`), **Realm Type** (**PvE / PvP only** — RP-PvE is later, needs the client
  UI-archive repack), **Welcome Message** (`MessageOfTheDay`).

Three build parts:
1. **Launcher (nusl.cpp):** a cogwheel button (top-right) → a small GDI+ Settings panel with editable
   fields (Win32 EDIT controls for name + welcome; a PvE/PvP toggle) + Save → writes `realm.json`.
2. **Engine (trivial):** `RealmType` from config → `RealmEntry.PvpType` (currently hardcoded 2).
3. **Engine — the welcome broadcast (RE'd this session):** send `MessageOfTheDay` as a **RealmBroadcast**.
   - **Opcode = `0x03E1` (993).** Body = `{ tier (u32), wide-string message }`. Reversed from
     `sub_140045A70` (the account/realm dispatcher, `WS+0x45A70`): line 55 fires the Lua `"RealmBroadcast"`
     event when `a3 == 993`. Cross-verified — the **same dispatcher** routes `a3==1889 (0x0761)` and
     `a3==1953 (0x07A1)` to `sub_140045E30`/`sub_1400461E0`, the exact handlers we already reversed, so
     `a3` is the wire opcode. Struct: tier @+0, string ptr @+8.
   - **Where it shows:** the char-select top-left area (`wndServerMessage`) — client
     `PreGame/Character/Character.lua::HelperServerMessages` (L4465): if
     `CharacterScreenLib.WasDisconnectedForLag()` → red lag string
     (`Apollo.GetString("CharacterSelect_LagDisconnectExplain")`), **else** the server realm messages
     (`GetLastRealmMessages` / `OnRealmBroadcast`, yellow). Also shown at Login + RealmSelect screens.
   - **CAVEAT — the "server lag" text is transient, NOT a permanent message.** It shows only because our
     restart-testing drops the socket abruptly → the client sets the lag flag, which **overrides** server
     messages. A real player on a stable server (clean login) sees the welcome. Optional: make server
     shutdown graceful (send a proper logout before closing) so the lag flag stops firing during our own
     testing.
